Engineering OS

How to work with it, day to day

Install once, set up each project once, then keep working the way you already do. It steps in only when a change is risky, something is about to leave your machine, or work claims to be done without proof.

Works in
Terminal, Desktop Code tab, VS Code and JetBrains, phone via Remote Control
Doesn't work in
Desktop Chat tab, claude.ai, Cowork
You need
Claude Code with fail-closed hooks, Node, a git repo
Protects against
Mistakes and injected instructions. Not a sandbox.

This guide describes v0.1 as built and tested (79 automated tests on Windows, macOS and Linux, plus runs in real Claude Code).

1. Install Once

One install at user level serves every project on your machine.

Check first

  • Claude Code 2.1.321 or later.
  • Node 18 or later on your PATH (tested on 20 and 24, on Windows, macOS and Linux). The hooks are a small Node script with no dependencies.
  • git. Edits are only allowed inside a git repo.

Install

# inside Claude Code
/plugin marketplace add eslamatwa/engineering-os
/plugin install engos@engineering-os

# or from a terminal
claude plugin install engos --marketplace eslamatwa/engineering-os

If Node is missing or Claude Code is too old, Engineering OS doesn't fail silently. It blocks edits and tells you what to install or update.

2. Set Up a Project

Open the project in Claude Code and run /engos:init. It asks a few questions and writes a small .engos/ folder.

What it asks

  1. No git? It offers git init. Say no and the project stays read-only.
  2. Which models do you have? Haiku, Sonnet, Opus, Fable. Saved so it never routes to one you don't have.
  3. How do you run checks? Your test, lint and build commands. Only these count as proof.
  4. Extra protection? Optional deny rules and the status line for this project. Your choice.
  5. What fits this project? At the end it lists the official skills and MCP servers that match your stack, with the commands to install them. Nothing is installed for you.

What it writes

.engos/
├── config.yaml   # committed: your settings
├── BRIEF.md      # committed: goal, constraints
├── STATE.yaml    # committed: facts, decisions
├── tasks/        # local only
├── approvals/    # local only
└── ledger.jsonl  # local only

Local-only files are added to .gitignore for you.

Spend two minutes on BRIEF.md and on the sensitive folders in config.yaml. Protected paths are the strongest protection you have; section 8 shows how.

3. Work as Usual

You don't choose a mode. Ask for what you want; the size of the work decides how much process it gets, and it can only go up.

question"Where is the session timeout set?"Answered directly. Nothing recorded.
trivial_edit"Rename tmp to buffer in io.py"Done by the main session. You see the diff and the test result.
standard"Fix the bug where expiry doesn't refresh"A plan, a worker agent, checks recorded, a short review.
high_risk"Change the login timeout"Touches auth/: you approve the files first and confirm at the end.

What moves a task up

  • Touching a protected folder like auth/, migrations/ or .env.
  • Going past a small edit: more than 2 files or 40 lines.
  • Sensitive requests, in any language: auth, payments, secrets, migrations, deployment.
  • Unknown commands are watched; in a high_risk task they need your approval.

What you'll see when it steps in

● Update(src/auth/session.ts)

  1 -export const timeout = 30;
  1 +export const timeout = 60;
 Do you want to make this edit?
 ❯ 1. Yes

Claude Code's own prompt, shown the first time a protected file is edited in a task.

A task only closes when the required proof exists: checks run through engos check after the last edit, the changed files are inside the plan, and the remaining risk is written down. "It works" from the model is not proof.

4. When You're Asked to Approve

Anything that leaves your machine or touches a protected file waits for your click in Claude Code's own Allow/Deny prompt. You see the real command or file, never a summary, and the model can't click it for you.

KindWhenHow you answerLasts
Single actionpush, publish, network call, delete, unknown command in a high_risk task, an external MCP tool (Slack, GitHub…). Claude's own app tools never ask.Click Yes or No in the promptThat one run; the next one asks again
Protected fileThe first edit of each protected file in a taskClick Yes or No in the promptThat file, until the task closes, max 24 hours
DecisionA command changed protected files without asking, so the task stoppedType /engos:decide TASK-… accept or stopThat decision only
Claude wants to run: git push origin fix/session-refresh branch fix/session-refresh commits 4e1a9c0 Refresh expiry on activity 7b2d113 Add refresh test approval APR-9f2c41d7 · once · expires 11:06 [ Allow ] [ Deny ]

Good to know

  • The prompt appears in every mode, including auto and bypass, even if your settings allow the command.
  • It shows the command itself. Extra context, like which commits a push sends, is in /engos:status.
  • Ordinary code files never ask. Most days you'll only be asked when you push.
  • Running headless or in CI? Anything that needs approval is refused.

5. When It Asks About Fable

Fable is for the hardest work, like architecture and migrations, and not every plan includes it. So it's never used without your yes.

Step S2 is a good fit for Fable. Moving sessions to tokens touches 14 files across 3 services and needs a data migration. To use Fable, type: /engos:decide TASK-014 fable To use Opus, type: /engos:decide TASK-014 no_fable

How it works

  • Asked per task, and your answer is recorded. Only your typed answer in the same session counts.
  • If fable isn't in models.available, you aren't asked: the step runs on Opus and you're told.
  • If a model call fails because your plan lacks it, it's marked unavailable and the step drops one tier.
  • After 3 failed attempts a task stops; Fable then appears only as one of the options you can pick.

6. Watching the Agents

Agents run in the background, so there are three ways to see what they're doing.

◆ engos TASK-012 standard │ lead opus │ scout ✓ │ worker sonnet S2 ⟳ 2/3 │ validator … │ ⚠ 1 approval

Status line

Always under the prompt: task, class, each agent with its model and step, attempts, failing checks, approvals waiting. Turn it on in /engos:init.

/engos:view

A live graph of the agents with a timeline, the proof collected and what's waiting for you. Select any agent or step to see its model, timing, the files it changed and its report. It refreshes every 2 seconds. In the Desktop app it opens beside the chat through a small local server (this machine only). It's view-only and can't approve anything.

/engos:status

The same picture as text in the chat. Handy from your phone through Remote Control.

7. When a Task Gets Blocked

A step gets three attempts: the first, a retry with the exact failure, then one stronger model. If it still fails, it stops and hands you the choice.

What you get

TASK-012 blocked: step S2 failed its checks 3 times
tried   sonnet, sonnet, opus
state   2 files changed · lint passes · test fails
options
  retry  one more attempt on Opus
  fable  one more attempt on Fable (if your plan has it)
  stop   stop; keep the changes for review
lead recommends  retry: the failing test needs …

How to answer

/engos:decide TASK-012 retry

You also decide when a script changed a protected file, when the worker and reviewer disagree on a high_risk task, and on any security finding of medium or higher.

Environment problems, like a missing tool, don't use up attempts. Two in one step come to you.

If the test itself is wrong, Claude proposes a change to the acceptance criteria. In a high_risk task you approve it with /engos:decide TASK-… approve_amendment.

8. Tuning a Project

Everything lives in .engos/config.yaml. You can add protection and tighten limits. You can't remove the built-in safety rules.

.engos/config.yaml

models:
  available: [haiku, sonnet, opus]
  ask_first: [deep]
checks:                # the only proof that counts
  test: "npm test"
  lint: "npm run lint"
protected_paths:
  high_risk:
    - "src/billing/**"   # your sensitive code
known_commands:        # never need approval
  - "npm run build"

Worth doing on day one

  • Add your sensitive folders. Code can't judge meaning. A pricing rule in an ordinary file is only protected if you list it.
  • Set real check commands. Without them, small edits close with "no checks configured" noted.
  • List the commands you run all the time so high_risk tasks don't ask about them.
  • Fill in BRIEF.md. Agents read it at the start of every session.

9. Commands

Commands marked "you" only count when you type them yourself.

CommandWhoWhat it does
/engos:inityouSet up the current project
/engos:decide TASK-… <option>youAnswer a task that stopped for you. The message tells you the options: accept/stop, retry/fable, fable/no_fable, close, validator/worker, approve_amendment/reject_amendment.
/engos:class TASK-… standardyouLower a task's class. Built-in safety rules stay.
/engos:pause · /engos:resumeyouTurn the extra process off or on for this session
/engos:statusanyoneShow the current task, agents, checks and what's waiting, as text
/engos:viewanyoneOpen the live graph
/engos:recommendanyoneThe official skills and MCP servers that fit your project, with why and the commands to install them. It never installs anything itself.

10. Pausing It

For quick hacking where plans and reviews get in the way.

/engos:pause turns off

  • Automatic tasks and classes
  • Plans and reviews
  • The proof check at the end

Still on, always

  • Your approval for push, publish, network, deletes and external MCP tools
  • The built-in no-go files: approvals, ledger, Claude settings, hooks
  • No production deploys

A pause lasts for the current session only. The next session starts with everything on again.

11. What It Won't Do

Knowing the limits is part of using it well.

Not a sandbox

It prevents common mistakes and detects indirect changes inside the repo after they happen. A model deliberately working around it, or a script changing files outside the repo, isn't stopped.

Not for servers yet

v0.1 works on code inside a git repo. It reads logs you give it but doesn't connect to servers, run commands on them, or deploy to production. That's planned for a later version.

No cost numbers

It records which model ran, how long and how many tool calls, but not token cost. Claude Code doesn't give that to plugins.

Your approval is final

It shows you the exact command, but if you approve something harmful, it runs. Read the command, not the explanation.

12. Troubleshooting

Every refusal comes with a reason. These are the common ones.

You seeWhyWhat to do
Every edit is blockedNode missing, Claude Code too old, or .engos/config.yaml broken. The session is in safe read-only mode.Follow the message: install Node, update Claude Code, or fix the config.
"Not a git repo"Edits need git.Run git init or accept it in /engos:init.
"Protected path"The file matches a protected folder.Click Yes in the prompt when Claude edits it.
"Outside the plan's scope"The change touches files the plan didn't list.Let Claude widen the scope (twice per task), or approve a decision.
My decision was ignoredTyped in another session, or after the session was resumed.Ask Claude to run engos task rearm TASK-…, then type the decision again in this session.
Tests passed but the task won't closeThey weren't run through engos check, or ran before the last edit.Ask Claude to run engos check test again.
No status lineIt's off unless you chose it in /engos:init, and it may not show in the Desktop app.Run /engos:init again and say yes to the status line, or use /engos:view, which opens beside the chat.
It keeps asking about a commandUnknown commands need approval in high_risk tasks.Add it to known_commands.
In short
  • Install once, run /engos:init in each project, then work normally.
  • Small work stays fast; risky work gets a plan, a review and your approval.
  • You always see the exact command before anything leaves your machine.
  • Protect your sensitive folders in config.yaml; it's your strongest setting.
  • Watch the agents with the status line, /engos:view or /engos:status.
