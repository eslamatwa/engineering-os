دليل Engineering OS

كيف تعمل معه يومًا بيوم

ثبّته مرة واحدة، وجهّز كل مشروع مرة واحدة، ثم اعمل كما تعمل عادةً. لا يتدخل إلا عندما يكون التغيير خطرًا، أو عندما يوشك شيء أن يغادر جهازك، أو عندما يُقال إن العمل انتهى دون دليل.

يعمل في
الطرفية، وتبويب Code في تطبيق Desktop، وVS Code وJetBrains، والهاتف عبر Remote Control
لا يعمل في
تبويب Chat في Desktop، وclaude.ai، وCowork
تحتاج
Claude Code يدعم الـ hooks التي تفشل مغلقة، وNode، ومستودع git
يحمي من
الأخطاء والتعليمات المدسوسة. ليس sandbox.

هذا الدليل يصف الإصدار 0.1 كما بُني واختُبر (79 اختبارًا آليًا على Windows وmacOS وLinux، وتجارب في Claude Code الحقيقي).

English version

١ التثبيت٢ تجهيز مشروع٣ العمل المعتاد٤ الموافقات٥ Fable٦ متابعة الـ agents٧ المهام المتوقفة٨ الإعدادات٩ الأوامر١٠ الإيقاف المؤقت١١ الحدود١٢ حل المشكلات

١. التثبيت مرة واحدة

تثبيت واحد على مستوى حسابك يخدم كل المشاريع على جهازك.

تأكد أولًا من

  • Claude Code بإصدار 2.1.321 أو أحدث.
  • Node بإصدار 18 أو أحدث في الـ PATH (جُرّب على 20 و24، على Windows وmacOS وLinux). الـ hooks سكريبت Node صغير بلا مكتبات خارجية.
  • git. التعديل مسموح داخل مستودع git فقط.

التثبيت

# inside Claude Code
/plugin marketplace add eslamatwa/engineering-os
/plugin install engos@engineering-os

# or from a terminal
claude plugin install engos --marketplace eslamatwa/engineering-os

إذا كان Node غير موجود أو كان Claude Code قديمًا، فلن يفشل Engineering OS بصمت. سيمنع التعديلات ويخبرك بما يجب تثبيته أو تحديثه.

٢. تجهيز مشروع

افتح المشروع في Claude Code وشغّل /engos:init. سيسألك بعض الأسئلة وينشئ مجلد .engos/ صغيرًا.

ماذا يسأل

  1. لا يوجد git؟ يعرض تشغيل git init. إذا رفضت يبقى المشروع للقراءة فقط.
  2. ما النماذج المتاحة لك؟ Haiku وSonnet وOpus وFable. تُحفظ الإجابة حتى لا يوجّه العمل إلى نموذج ليس لديك.
  3. كيف تشغّل الفحوصات؟ أوامر الاختبار والـ lint والبناء. هذه وحدها تُحسب دليلًا.
  4. حماية إضافية؟ قواعد deny وسطر الحالة لهذا المشروع، اختياريًا.
  5. ما المناسب لمشروعك؟ في النهاية يعرض الـ skills وخوادم MCP الرسمية المناسبة لمشروعك مع أوامر تثبيتها. لا يُثبَّت أي شيء نيابةً عنك.

ماذا ينشئ

.engos/
├── config.yaml   # committed: your settings
├── BRIEF.md      # committed: goal, constraints
├── STATE.yaml    # committed: facts, decisions
├── tasks/        # local only
├── approvals/    # local only
└── ledger.jsonl  # local only

الملفات المحلية تُضاف إلى .gitignore تلقائيًا.

خصّص دقيقتين لملف BRIEF.md وللمجلدات الحساسة في config.yaml. المسارات المحمية أقوى حماية لديك، والقسم ٨ يشرح كيف.

٣. اعمل كالمعتاد

لا تختار وضعًا معينًا. اطلب ما تريد، وحجم العمل يحدد مقدار الإجراءات، ودرجته ترتفع فقط ولا تنخفض.

question«أين يُضبط مهلة الجلسة؟»إجابة مباشرة. لا شيء يُسجّل.
trivial_edit«غيّر اسم tmp إلى buffer في io.py»الجلسة الرئيسية تنفذه. ترى الـ diff ونتيجة الاختبار.
standard«أصلح خطأ عدم تجديد انتهاء الجلسة»خطة، وworker، وفحوصات مسجلة، ومراجعة قصيرة.
high_risk«غيّر مهلة تسجيل الدخول»يلمس auth/: توافق على الملفات أولًا وتؤكد في النهاية.

ما الذي يرفع درجة المهمة

  • لمس مجلد محمي مثل auth/ أو migrations/ أو .env.
  • تجاوز حدود التعديل الصغير: أكثر من 4 ملفات أو 40 سطرًا.
  • الطلبات الحساسة بأي لغة: المصادقة، والدفع، والأسرار، والـ migrations، والنشر.
  • الأوامر غير المعروفة تُراقب، وفي مهام high_risk تحتاج موافقتك.

ما الذي تراه عندما يتدخل

نافذة Claude Code نفسها، تظهر أول مرة يُعدَّل فيها ملف محمي داخل المهمة.

لا تُغلق المهمة إلا بوجود الدليل المطلوب: فحوصات شُغّلت عبر engos check بعد آخر تعديل، وملفات متغيرة داخل الخطة، ومخاطر متبقية مكتوبة. قول النموذج «إنه يعمل» ليس دليلًا.

٤. عندما يُطلب منك الموافقة

كل ما يغادر جهازك أو يلمس ملفًا محميًا ينتظر ضغطتك في نافذة السماح والرفض الخاصة بـ Claude Code نفسها. ترى الأمر أو الملف الحقيقي، لا ملخصًا عنه، ولا يستطيع النموذج الضغط بدلًا منك.

النوعمتىكيف تردالمدة
إجراء واحدpush، أو نشر، أو اتصال شبكي، أو حذف، أو أمر غير معروف في مهمة high_risk، أو أداة MCP خارجية (Slack وGitHub…). أدوات Claude الداخلية لا تسألك أبدًا.اضغط Yes أو No في النافذةهذه المرة فقط؛ المرة التالية تسألك من جديد

قرارأمر غيّر ملفات محمية دون أن يسأل، فتوقفت المهمةاكتب /engos:decide TASK-… accept أو stopلهذا القرار فقط

معلومات مهمة

  • تظهر النافذة في كل الأوضاع، بما فيها auto وbypass، حتى لو كانت إعداداتك تسمح بالأمر.
  • تعرض الأمر نفسه. السياق الإضافي، مثل الـ commits التي سيرسلها الـ push، موجود في /engos:status.
  • ملفات الكود العادية لا تسأل أبدًا. في أغلب الأيام لن يسألك إلا عند الـ push.
  • تعمل بلا واجهة أو في CI؟ كل ما يحتاج موافقة يُرفض.

٥. عندما يسأل عن Fable

Fable مخصص لأصعب الأعمال مثل التصميم المعماري والـ migrations، وليس متاحًا في كل الاشتراكات. لذلك لا يُستخدم أبدًا دون موافقتك.

Step S2 is a good fit for Fable. Moving sessions to tokens touches 14 files across 3 services and needs a data migration. To use Fable, type: /engos:decide TASK-014 fable To use Opus, type: /engos:decide TASK-014 no_fable

كيف يعمل

  • يُسأل لكل مهمة على حدة، وتُسجّل إجابتك. لا تُحسب إلا إجابتك المكتوبة في نفس الجلسة.
  • إذا لم يكن fable ضمن models.available فلن تُسأل: تعمل الخطوة على Opus ويُبلغك بذلك.
  • إذا فشل استدعاء نموذج لأنه غير متاح في اشتراكك، يُعلَّم كغير متاح وتنزل الخطوة درجة واحدة.
  • بعد 3 محاولات فاشلة تتوقف المهمة، ويظهر Fable كأحد الخيارات التي تختار منها.

٦. متابعة الـ agents

الـ agents تعمل في الخلفية، لذلك هناك ثلاث طرق لترى ما تفعله.

◆ engos TASK-012 standard │ lead opus │ scout ✓ │ worker sonnet S2 ⟳ 2/3 │ validator … │ ⚠ 1 approval

سطر الحالة

دائمًا تحت الـ prompt: المهمة، ودرجتها، وكل agent مع نموذجه وخطوته، والمحاولات، والفحوص الفاشلة، والموافقات المنتظرة. تفعّله من /engos:init.

/engos:view

رسم حي للـ agents مع خط زمني، والأدلة المجمّعة، وما ينتظرك. اضغط على أي agent أو خطوة لترى نموذجه، ووقته، وتكلفته، والملفات التي غيّرها، وتقريره. وفيه خط زمني لكل agent، وتكلفة المهمة لكل نموذج، وتعديلات كل ملف، وإعادة تشغيل مهمة انتهت، وتاريخ الفحوص، وتقرير للتصدير، وكل مشاريعك. ويتحوّل للعربية بضغطة. يتحدّث كل ثانيتين. في تطبيق Desktop يفتح بجانب المحادثة عبر خادم محلي صغير (على جهازك فقط). للعرض فقط ولا يستطيع الموافقة على أي شيء.

/engos:status

نفس الصورة كنص في المحادثة. مفيد من الهاتف عبر Remote Control.

٧. عندما تتوقف مهمة

كل خطوة لها ثلاث محاولات: الأولى، ثم إعادة مع الخطأ الحرفي، ثم نموذج أقوى بدرجة. إذا استمر الفشل تتوقف ويعود القرار إليك.

ما الذي يصلك

TASK-012 blocked: step S2 failed its checks 3 times
tried   sonnet, sonnet, opus
state   2 files changed · lint passes · test fails
options
  retry  one more attempt on Opus
  fable  one more attempt on Fable (if your plan has it)
  stop   stop; keep the changes for review
lead recommends  retry: the failing test needs …

كيف ترد

/engos:decide TASK-012 retry

تقرر أنت أيضًا عندما يغيّر سكريبت ملفًا محميًا، وعندما يختلف الـ worker والمراجع في مهمة high_risk، وفي أي ملاحظة أمنية بدرجة متوسطة أو أعلى.

مشكلات البيئة، مثل أداة ناقصة، لا تستهلك محاولات. وإذا تكررت مرتين في نفس الخطوة تصل إليك.

إذا كان الاختبار نفسه خاطئًا، يقترح Claude تعديل شروط القبول. وفي مهمة high_risk توافق عليه بـ /engos:decide TASK-… approve_amendment.

٨. ضبط إعدادات المشروع

كل شيء في .engos/config.yaml. يمكنك إضافة حماية وتشديد الحدود، لكن لا يمكنك إزالة قواعد الأمان المدمجة.

.engos/config.yaml

models:
  available: [haiku, sonnet, opus]
  ask_first: [deep]
checks:                # the only proof that counts
  test: "npm test"
  lint: "npm run lint"
protected_paths:
  high_risk:
    - "src/billing/**"   # your sensitive code
known_commands:        # never need approval
  - "npm run build"

يستحق أن تفعله من اليوم الأول

  • أضف مجلداتك الحساسة. الكود لا يفهم المعنى. قاعدة تسعير في ملف عادي لا تكون محمية إلا إذا أضفتها.
  • حدد أوامر فحص حقيقية. بدونها تُغلق التعديلات الصغيرة مع ملاحظة «لا توجد فحوصات».
  • أضف الأوامر التي تستخدمها دائمًا حتى لا تسألك مهام high_risk عنها.
  • املأ BRIEF.md. تقرؤه الـ agents في بداية كل جلسة.

٩. الأوامر

الأوامر المكتوب أمامها «أنت» لا تُحسب إلا إذا كتبتها بنفسك.

الأمرمنماذا يفعل
/engos:initأنتتجهيز المشروع الحالي
/engos:decide TASK-… <option>أنتالرد على مهمة توقفت تنتظرك. الرسالة تخبرك بالخيارات: accept/stop، retry/fable، fable/no_fable، close، validator/worker، approve_amendment/reject_amendment.
/engos:class TASK-… standardأنتخفض درجة مهمة. قواعد الأمان المدمجة تبقى.
/engos:pause · /engos:resumeأنتإيقاف الإجراءات الإضافية أو تشغيلها لهذه الجلسة
/engos:statusأي أحدعرض المهمة الحالية والـ agents والفحوص وما ينتظرك، كنص
/engos:viewأي أحدفتح الرسم الحي
/engos:recommendأي أحدأفضل الـ skills وخوادم MCP الرسمية المناسبة لمشروعك، مع سبب كل اقتراح وأوامر التثبيت. لا يثبّت أي شيء بنفسه.

١٠. الإيقاف المؤقت

للتجربة السريعة عندما تعطلك الخطط والمراجعات.

/engos:pause يوقف

  • المهام والدرجات التلقائية
  • الخطط والمراجعات
  • فحص الدليل عند الإغلاق

يبقى شغالًا دائمًا

  • موافقتك على push والنشر والشبكة والحذف وأدوات MCP الخارجية
  • الملفات الممنوعة المدمجة: الموافقات، والـ ledger، وإعدادات Claude، والـ hooks
  • لا نشر على production

الإيقاف يستمر للجلسة الحالية فقط. الجلسة التالية تبدأ وكل شيء يعمل من جديد.

١١. ما لن يفعله

معرفة الحدود جزء من الاستخدام الصحيح.

ليس sandbox

يمنع الأخطاء الشائعة ويكشف التغييرات غير المباشرة داخل المستودع بعد حدوثها. لا يوقف نموذجًا يحاول التحايل عمدًا، ولا سكريبت يغيّر ملفات خارج المستودع.

ليس للخوادم بعد

الإصدار 0.1 يعمل على الكود داخل مستودع git. يقرأ السجلات التي تعطيها له، لكنه لا يتصل بالخوادم، ولا ينفذ أوامر عليها، ولا ينشر على production. هذا مخطط لإصدار لاحق.

لا أرقام للتكلفة

يسجّل أي نموذج عمل، وكم استغرق، وعدد استدعاءات الأدوات، لكن ليس تكلفة الـ tokens. Claude Code لا يعطي هذه البيانات للـ plugins.

موافقتك نهائية

يعرض لك الأمر الحرفي، لكن إذا وافقت على شيء ضار فسيُنفذ. اقرأ الأمر نفسه، لا الشرح.

١٢. حل المشكلات

كل رفض يأتي مع سببه. هذه أكثرها شيوعًا.

ما تراهالسببماذا تفعل
كل التعديلات ممنوعةNode غير موجود، أو Claude Code قديم، أو .engos/config.yaml تالف. الجلسة في وضع القراءة فقط الآمن.اتبع الرسالة: ثبّت Node، أو حدّث Claude Code، أو أصلح الإعدادات.
«ليس مستودع git»التعديل يحتاج git.شغّل git init أو وافق عليه في /engos:init.
«مسار محمي»الملف داخل مجلد محمي.اضغط Yes في النافذة عندما يعدّله Claude.
«خارج نطاق الخطة»التغيير يلمس ملفات لم تذكرها الخطة.اترك Claude يوسّع النطاق (مرتين لكل مهمة)، أو وافق على قرار.
قراري تم تجاهلهكُتب في جلسة أخرى، أو بعد استئناف الجلسة.اطلب من Claude تشغيل engos task rearm TASK-…، ثم اكتب القرار مرة أخرى في هذه الجلسة.
الاختبارات نجحت لكن المهمة لا تُغلقلم تُشغّل عبر engos check، أو شُغّلت قبل آخر تعديل.اطلب من Claude تشغيل engos check test مرة أخرى.
لا يظهر سطر الحالةهو مُطفأ إلا إذا اخترته في /engos:init، وقد لا يظهر في تطبيق Desktop.شغّل /engos:init مرة أخرى ووافق على سطر الحالة، أو استخدم /engos:view، فهو يفتح بجانب المحادثة.
يسألني عن أمر باستمرارالأوامر غير المعروفة تحتاج موافقة في مهام high_risk.أضفه إلى known_commands.
باختصار
  • ثبّته مرة، وشغّل /engos:init في كل مشروع، ثم اعمل كالمعتاد.
  • العمل الصغير يبقى سريعًا، والعمل الخطر يأخذ خطة ومراجعة وموافقتك.
  • ترى دائمًا الأمر الحرفي قبل أن يغادر أي شيء جهازك.
  • احمِ مجلداتك الحساسة في config.yaml؛ إنه أقوى إعداد لديك.
  • تابع الـ agents بسطر الحالة أو /engos:view أو /engos:status.
